# Module 12.6.6 validation results

Windows validation run: 9 October 2026. Physical devices were not exercised.

## Automated scope

The new tests run the real always-on loop, wake activation, assistant routing,
passive worker, extraction, SQLite, retrieval, reminder notifications and
scheduler. Audio devices, speech recognition and speech synthesis are mocked.
Additional boundary tests exercise real RMS VAD and WAV writing using synthetic
audio callbacks, and real Whisper/Piper/Ollama adapters using fake subprocesses
or HTTP responses.

All five target passive statements are stored without a wake word, then recalled
through wake-word questions and dispatched to TTS and playback. Coverage includes
duplicate prevention, negation, unsupported model candidates, contradictory
observations, confirmed-fact priority, missing information, no recall writes,
nonblocking background extraction, reminder interruption, listening resumption,
Ctrl+C at three stages, recovery and fresh application restart cycles.

Final suite: **421 passed in 62.39 seconds**. Tests use temporary databases and
mock devices, never the personal memory database.

Five synthetic observations were seeded through real deterministic extraction.
Twenty duplicate extraction/recall rounds left exactly five observations stored.
The optional audio run used a separate empty database. Installed Piper
synthesized each passive statement; its file was resampled to 16 kHz and
transcribed by installed Whisper before real extraction and SQLite storage.
All five observations were saved. Each wake question was also synthesized,
transcribed, routed through wake detection and recall, and answered with response
audio generated by installed Piper. All five answers contained the required
information. The audio database had five observations at completion; pre-seeded
text observations could not mask a transcription failure.

No microphone was opened and no audio was played. File-response timings omit
capture/VAD, physical playback and the voice loop's playback-settling delay.
Piper samples include passive statement, question and response synthesis. Deterministic
extraction timings include initial writes and mostly duplicate checks, not LLM
extraction. The Ollama probe is one short fixed-prompt generation, not a latency
distribution or validation of memory extraction accuracy. Tests and the benchmark
ran during the same verification period, so these figures are indicative and
may reflect machine contention. They are not Raspberry Pi measurements.

## Windows acceptance remains open

The live checklist must still be completed by a person using the physical
microphone and speaker. Wired mute controls are absent; capture pauses during
processing/playback; echo/noise, real model extraction, queue capture timestamps
and long-duration stability remain risks detailed in that checklist.
Raspberry Pi deployment remains deferred.
